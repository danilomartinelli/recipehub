## 7. Restrições & Casos Limite

### Restrições Técnicas

| # | Restrição |
|---|---|
| R-1 | **Zero JavaScript no cliente.** O Astro deve ser configurado com `output: 'static'`. Nenhum componente com `client:load`, `client:idle` ou qualquer outra diretiva de hidratação é permitido. |
| R-2 | **Sem dependências de Node.js.** Embora esta seja uma build estática (não um Worker), a regra de Edge Compatibility da doutrina deve ser respeitada para manter consistência de padrões no monorepo. |
| R-3 | **Reutilização obrigatória do BaseLayout.** O `apps/web/src/layouts/BaseLayout.astro` já existe e está mapeado no `code-map.md`. PROIBIDO criar `Layout.astro` ou qualquer arquivo de layout alternativo. |
| R-4 | **TailwindCSS via config base.** Usar `tooling/tailwind/base.ts` como preset — não instalar uma cópia isolada do Tailwind em `apps/web`. |
| R-5 | **Fonte via `<link>` no `<head>`, não via `@import` CSS.** O `@import` em CSS bloqueia o render. Usar `<link rel=\"preconnect\">` + `<link rel=\"stylesheet\">` para a fonte Inter. |
| R-6 | **Imagens com dimensões explícitas.** Todos os `<img>` devem ter `width` e `height` definidos para evitar Cumulative Layout Shift (CLS) e manter score Lighthouse alto. |

### Casos Limite

| # | Cenário | Comportamento Esperado |
|---|---|---|
| CL-1 | Usuário clica em \"Explorar Receitas\" sem suporte a `scroll-behavior: smooth` (browser antigo) | Scroll instantâneo para `#recipes` — comportamento nativo do browser, sem fallback JS necessário. |
| CL-2 | Usuário submete o formulário de newsletter | Browser realiza GET para `index.html#` (action=\"#\"). A página recarrega mas **nada é enviado**. Comportamento esperado e documentado. |
| CL-3 | `placehold.co` indisponível | As imagens mostram o broken image icon nativo do browser. Aceitável para placeholder — não é conteúdo crítico. |
| CL-4 | Google Fonts bloqueado (ex: China, redes corporativas) | O browser cai para a font-stack de fallback: `Inter, system-ui, -apple-system, sans-serif`. A página permanece legível. |
| CL-5 | Deploy no Cloudflare Pages com `_headers` ou `_redirects` | Não são necessários arquivos customizados. O Cloudflare Pages serve o `dist/` estático com headers padrão adequados. |
