### 2.3 Estado do Formulário de Newsletter

Sem persistência. O estado é gerenciado puramente via JavaScript inline no componente Astro:

```typescript
// Estado local do formulário (client-side script dentro do componente)
interface NewsletterFormState {
  email: string;       // valor do campo
  error: string | null; // mensagem de erro de validação
  submitted: boolean;  // flag de sucesso visual (sem chamada de API)
}
```

**Fluxo de submit:**
1. Usuário digita email e clica em \"Quero Receber\"
2. Validação: campo obrigatório + regex de formato de email
3. Se inválido: exibir mensagem de erro abaixo do campo
4. Se válido: esconder formulário e exibir mensagem de sucesso (\"Obrigado! Em breve você receberá nossas novidades.\")
5. **Nenhuma requisição HTTP é disparada**

## 5. Requisitos Funcionais

### REQ-001 — Hero: Conteúdo Textual
**Prioridade:** MUST  
O componente `HeroSection.astro` deve renderizar:
- Um `<h1>` com o título principal do produto (ex: \"Descubra Receitas Incríveis\")
- Um parágrafo `<p>` com subtítulo descritivo (ex: \"Encontre inspiração para cada refeição. Receitas selecionadas por chefs e cozinheiros apaixonados.\")
- Um elemento âncora `<a>` estilizado como botão, com texto \"Explorar Receitas\" e `href=\"#receitas\"` (âncora para a seção de cards na mesma página)

### REQ-002 — Hero: Visual e Responsividade
**Prioridade:** MUST  
A hero section deve ter altura mínima de `80vh`, background com cor sólida ou gradiente (usando variáveis TailwindCSS), e o texto deve ser legível (contraste mínimo WCAG AA). Em mobile (< 768px), o layout deve ser em coluna centralizada. Em desktop (≥ 768px), pode ser dois-colunas ou centralizado.

### REQ-003 — Cards: Dados Mockados
**Prioridade:** MUST  
Os dados dos 6 cards devem ser importados exclusivamente de `apps/web/src/data/featured-recipes.ts` (ver seção 2.2). É proibido hardcodar os dados diretamente nos arquivos `.astro`.

### REQ-004 — Cards: Estrutura do Componente `RecipeCard.astro`
**Prioridade:** MUST  
O componente deve receber as props do tipo `RecipeCard` (importado de `featured-recipes.ts`) e renderizar:
- `<img src={image_url} alt={title} loading=\"lazy\" width=\"600\" height=\"400\" />`
- `<h3>` com o título da receita
- `<span>` ou `<p>` com o nome da categoria
- `<span>` com o tempo de preparo formatado: `{prep_time} min`
- O elemento raiz do card deve ser `<article>`

### REQ-005 — Cards: Grid Responsivo
**Prioridade:** MUST  
O componente `RecipesGrid.astro` deve renderizar os 6 cards em um grid CSS:
- Mobile (< 640px): 1 coluna
- Tablet (≥ 640px, < 1024px): 2 colunas
- Desktop (≥ 1024px): 3 colunas

Implementar via classes TailwindCSS: `grid grid-cols-1 sm:grid-cols-2 lg:grid-cols-3 gap-6`.

### REQ-006 — Newsletter: Renderização do Formulário
**Prioridade:** MUST  
O componente `NewsletterForm.astro` deve renderizar uma seção com:
- Título `<h2>` (ex: \"Fique por Dentro\")
- Subtítulo `<p>` (ex: \"Receba as melhores receitas diretamente no seu email.\")
- `<label for=\"newsletter-email\">Seu email</label>`
- `<input type=\"email\" id=\"newsletter-email\" name=\"email\" placeholder=\"voce@exemplo.com\" />`
- `<button type=\"submit\">Quero Receber</button>`
- `<p id=\"newsletter-error\" aria-live=\"polite\"></p>` — container de erro (inicialmente vazio)
- `<div id=\"newsletter-success\" hidden>Obrigado! Em breve você receberá nossas novidades.</div>`

### REQ-007 — Newsletter: Validação de Email
**Prioridade:** MUST  
Um `<script>` dentro de `NewsletterForm.astro` deve interceptar o evento `submit` do formulário via `addEventListener('submit', handler)` e:
1. Chamar `event.preventDefault()` para bloquear o envio HTTP nativo do browser
2. Limpar a mensagem de erro anterior
3. Se campo vazio: exibir \"Por favor, insira seu email.\" no elemento `#newsletter-error`
4. Se formato inválido (validar via regex `/^[^\\s@]+@[^\\s@]+\\.[^\\s@]+$/`): exibir \"Por favor, insira um email válido.\"
5. Se válido: esconder o `<form>` e exibir `#newsletter-success`

### REQ-008 — Newsletter: Nenhuma Requisição HTTP
**Prioridade:** MUST  
O formulário NÃO deve possuir atributo `action` com URL. O submit não deve disparar nenhuma requisição HTTP. Verificável via DevTools > Network ao submeter email válido.
